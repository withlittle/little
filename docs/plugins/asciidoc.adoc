= AsciiDoc
:description: Build each AsciiDoc file into a page, without Asciidoctor or Ruby, with the asciidoc plugin.

`asciidoc`, one of link:using-plugins.md#littles-own-plugins[little's own plugins], makes each https://asciidoc.org[AsciiDoc] file in `docs/`, `.adoc` or `.asciidoc`, a link:using-plugins.md#pages-in-other-formats[page], without Asciidoctor or Ruby.
Name it in your site's link:using-plugins.md#naming-a-plugin[`plugins`]:

[source,yaml]
----
# little.yml
plugins:
  asciidoc: https://github.com/withlittle/little/releases/download/asciidoc-v0.1.0/little_asciidoc.wasm
----

It has no settings.
This page is one AsciiDoc file, `docs/plugins/asciidoc.adoc`.

== The header

The document's title, `+= Title+`, is the page's title and its `#` heading, and its `+:description:+` is the page's description.
The author and revision lines under the title are left out.
A page can also start with link:../writing/frontmatter.md#in-another-format[frontmatter], above its title, which goes over the header.

== Text

AsciiDoc's markup is Markdown's where Markdown has it: *bold*, _italic_, `monospace`, and [.line-through]#struck through#.
Where it hasn't, it's HTML: #highlighted# is `<mark>`, ^super^script `<sup>`, ~sub~script `<sub>`, and [.underline]#underlined# `<u>`, or Markdown, where your site turns on the link:../writing/markdown.md#choosing-markdowns-extensions[extension] for it, like `mark`.
Other roles, like `+[.lead]+`, are dropped, and their text is kept.

Attribute references, like `+{nbsp}+` or one to your own attribute, character references, like `+&#8594;+`, and replacements, like `+(C)+` for (C), show what Asciidoctor shows.
A line that ends in `{plus}`, or a paragraph marked `+[%hardbreaks]+`, keeps its line breaks.

With `+:experimental:+` in the header, as in Asciidoctor, a key, `+kbd:[Ctrl+C]+`, is code, a button, `+btn:[Save]+`, is bold, and a menu, `+menu:File[Save]+`, is its names, joined by ›.

== Sections and links

A section's title, `+== Title+`, is a heading with as many `#` as it has `=`, from `##` to `######`.
With `+:sectnums:+`, its title has its number, as Asciidoctor numbers it.
Its id leads to it too: the one Asciidoctor works out from its title, like `+_the_header+`, or one you give it, with `+[#id]+` or `+[[id]]+`.

A cross-reference, like `+<<_the_header>>+` or `+xref:_the_header[]+`, leads to the id on this page, and shows its section's title, as <<_the_header>> does.
One to another page, like `+xref:guide.adoc#install[]+` or `+<<guide.adoc#install,Installing>>+`, leads to that page, as `+link:../writing/markdown.md[]+` leads to a Markdown page.
An anchor, `+[[id]]+` or `+anchor:id[]+`, gives the place it's in an id to lead to, and a block's id leads to the block.

A URL, like https://docs.asciidoctor.org, is a link, as are `+https://example.com[text]+`, `+link:file.pdf[text]+`, and `+mailto:you@example.com[]+`.

== Lists

Each of AsciiDoc's lists is the Markdown list nearest it:

Bullets:: `+*+` or `+-+`, nested by the number of `+*+`, are a bulleted list.
Numbers:: `+.+`, nested by the number of `+.+`, are a numbered list. It starts at 1, or where `+[start=4]+` says.
Checklists:: `+* [x]+` and `+* [ ]+` are GitHub's task lists.
Terms:: A term and what it means, like these, are a description list.

A numbered list's style, like `+[loweralpha]+`, is lost, as Markdown numbers lists only with numbers.

== Code

A listing block, `+----+`, is a code block, highlighted in the language its `+[source,lang]+` names, or `+:source-language:+` sets.
A literal block, `+....+`, or an indented paragraph, is one with no language.
A code block goes to link:using-plugins.md#code-blocks[plugins] that render its language, and a `+[source,mermaid]+` block is a link:../writing/diagrams.md[diagram].
Callouts stay in the code, as you write them, and their list is a numbered list:

[source,yaml]
----
plugins:
  asciidoc: ./little_asciidoc.wasm # <1>
----
<1> A path to a `.wasm` file you've built works too.

== Admonitions

NOTE: An admonition is the alert of its name, like this note.
It's one of GitHub's five link:../writing/markdown.md#callouts[alerts]: `NOTE`, `TIP`, `IMPORTANT`, `WARNING`, or `CAUTION`.

A block, `+[NOTE]+` over `+====+`, can hold lists and code too.
An admonition's title, `+.Title+`, is its alert's.

== Other blocks

.What other blocks are
[cols="2,3"]
|===
|Block |In the page

|Quote, `+____+`
|A quote, ending with its attribution

|Verse, `+[verse]+`
|A quote that keeps its line breaks

|Example, `+====+`, sidebar, `+****+`, and open, `+--+`
|What they hold

|Passthrough, `pass:[++++]`
|Its HTML, as it is

|Thematic break, `+'''+`
|A rule

|Table of contents, `+toc::[]+`
|Nothing, as the theme has its own

|Page break, `+<<<+`
|Nothing

|Video, `+video::+`, and audio, `+audio::+`
|HTML's `<video>` and `<audio>`, or YouTube's or Vimeo's player
|===

A block's title, `+.Title+`, is a paragraph in italics above it, numbered as Asciidoctor numbers it, like this table's.

== Tables

A table, `+|===+`, is one of GitHub's tables, with its header row, if it has one.
Each column is aligned as `+cols+` says, with `+<+`, `+^+`, or `+>+`.
A CSV or DSV table, `+,===+` or `+:===+`, is one too.

Markdown's tables can't merge cells, or hold blocks, so a cell that spans columns or rows is written in its first place, with empty cells after it, and an `+a|+` cell's blocks are run together, a line each.
Each is warned of.

== Images

An image, `+image::file.png[Alt text]+`, is in a paragraph of its own, with its title below it.
One in a line, `+image:file.png[Alt text]+`, is in the line.
A relative path is in the folder `+:imagesdir:+` names, if it names one, and an image with `+link=+` is a link.
Without alt text, an image's alt text is its file's name, like `my diagram` for `my-diagram.png`.

== Footnotes

A footnote, `+footnote:[Its text.]+`, is numbered through the page, like this one.footnote:[Its text is at the foot of the page.]
Name it, `+footnote:name[Its text.]+`, and `+footnote:name[]+` refers to it again.

== Math

Math is TeX, written as link:../writing/math.md#choosing-how-math-is-written[`markdown.math`] says: `+latexmath:[...]+` in a line, like latexmath:[e^{i\pi} + 1 = 0], or a `+[latexmath]+` block, on its own.
`+stem:[...]+` and a `+[stem]+` block are TeX too, once the header sets `+:stem: latexmath+`.
Without that, they're AsciiMath, as is `+asciimath:[...]+`, which stays code, as little writes only TeX.

== What's different

The plugin reads AsciiDoc as Asciidoctor does, and leaves out what Asciidoctor's HTML leaves out, like comments, except that:

* An include, `+include::file.adoc[]+`, isn't followed. It's left out, and warned of.
* A macro the plugin doesn't read, like one from an extension of Asciidoctor's, is kept as text, and warned of.
* A collapsible block, `+[%collapsible]+`, is open, and can't be folded.
