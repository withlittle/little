#+TITLE: Org mode
#+DESCRIPTION: Build each Org mode file into a page, without Emacs, with the orgmode plugin.
#+OPTIONS: ^:{}

little's repository has a plugin, [[https://github.com/withlittle/little/tree/main/plugins/orgmode][=orgmode=]], that makes each [[https://orgmode.org][Org mode]] file (=.org=) in =docs/= a page, reading Org itself, without Emacs, or exporting it first.
This page is one, =docs/plugins/org-mode.org=, and a link to it from Markdown, like =[Org mode](org-mode.org)=, leads to its page.
[[file:../decisions/0060-other-formats-in-plugins.md][ADR 0060]] says why a plugin reads it, and [[file:../decisions/0062-plugins-for-asciidoc-and-orgmode.md][ADR 0062]] how its page is written.

* Getting it

Each version of =orgmode= is released in little's repository, as a =.wasm= file, about 0.6 MB, which a site names by its URL, with the version in it:

#+BEGIN_SRC text
https://github.com/withlittle/little/releases/download/orgmode-v0.1.0/little_orgmode.wasm
#+END_SRC

little downloads it in the site's first build, and uses that copy from then on, as for [[file:using-plugins.md::#naming-a-plugin][any plugin]], so to update it, change the URL to a later version's.
Its releases, among [[https://github.com/withlittle/little/releases][little's]], list what changed in each version, and the version of little's [[file:../reference/plugin-hooks.md][hooks]] it's built for, and each carries a =THIRD-PARTY-NOTICES.md=, with the licences of the crates it's built from.
To build it yourself, see its [[https://github.com/withlittle/little/tree/main/plugins/orgmode#building-it][README]].

* Using it

Name it in your site's =little.yml=, and each Org file in =docs/= is a page:

#+BEGIN_SRC yaml
# little.yml
plugins:
  orgmode: https://github.com/withlittle/little/releases/download/orgmode-v0.1.0/little_orgmode.wasm
#+END_SRC

It has no settings.
Without it, an Org file is copied into the site as it is, as any other file is.
A folder's =README.org= is its page, as a =README.md= is.

* The keywords

The file's =#+TITLE:= is the page's title, and its =#= heading, and its =#+DESCRIPTION:= is the page's description.
Each can be anywhere in the file, as in Org, and two =#+TITLE:= lines are joined, with a space.
Its =#+AUTHOR:=, =#+DATE:=, and =#+EMAIL:= are left out, as little's themes have no place for them, but a macro, like ={{{author}}}=, shows them.

A page can start with [[file:../writing/frontmatter.md::#in-another-format][frontmatter]] too, between =---= lines, above its keywords, as a Markdown page can, which goes over them, for any of little's keys, like =search: false=:

#+BEGIN_SRC org
---
search: false
---
#+TITLE: Release notes
#+DESCRIPTION: What changed in each version.
#+END_SRC

A macro that =#+MACRO:= defines, like =#+MACRO: kbd ~$1~=, is expanded, as Org expands it, as are =title=, =author=, =date=, =email=, =keyword=, and =results=.
=#+TODO:=, and its kin, =#+SEQ_TODO:= and =#+TYP_TODO:=, set the file's TODO keywords, and =#+PROPERTY: header-args= the header arguments of its blocks of code.
Of =#+OPTIONS:=, only =^:= and =-:= are read, as [[*Text]] says.

* Text

Org's markup is Markdown's where Markdown has it: *bold*, /italic/, =verbatim= and ~code~, which are both code, and +struck through+.
Where it hasn't, it's HTML: _underlined_ is =<u>=, and the 2 in x^{2} and H_{2}O is =<sup>= and =<sub>=.
With the [[file:../writing/markdown.md::#choosing-markdowns-extensions][extensions]] for them on, =superscript= and =subscript=, the last two are Markdown, and with neither those nor [[file:../writing/markdown.md::#html][HTML]], all three are plain text, and warned of.

Org's export reads =x^2= as a superscript too, and the =_case= of =snake_case= as a subscript, and so does the plugin, unless the file sets =#+OPTIONS: ^:{}=, as this page does, which reads only those in braces, like =x^{2}=, or =^:nil=, which reads none.

Text shows as Org's export shows it, even where Markdown would read it as markup, like the * in 2 * 3, or :smile:.
So =--= is an en dash, --, =---= an em dash, ---, and =...= an ellipsis, ..., unless the file sets =#+OPTIONS: -:nil=.
An entity, like =\alpha= or =\to=, is its character, \alpha or \to, and a line that ends in =\\= keeps its line break.

* Headlines and links

A headline, =* Title=, is a heading, with one more =#= than it has =*=, as the page's title is its =#=: =*= is =##=, and so on, to =######=.
Its =CUSTOM_ID= property, or a target, =<<name>>=, in its title, leads to it, beside the =#fragment= little gives it.
Its TODO keyword, priority, and tags are left out, as are its planning lines, like =SCHEDULED:=, and its drawers, but a block's results.
A headline that starts with =COMMENT=, or is tagged =:noexport:=, is left out, with all that's under it, as in Org's export.

A URL is a link, like https://orgmode.org, and so is =[[https://example.com][text]]=, =[[file:file.pdf][text]]=, or =<mailto:you@example.com>=.
A link to a headline, =[[*Using it]]=, or to its =CUSTOM_ID=, =[[#id]]=, leads to it, and shows its title, as [[*Using it]] does.
One to a target, =[[name]]=, leads to the target, =<<name>>=, or the table or block whose =#+NAME:= it is, and else to the headline of its title.
One to another page's file, like =[[file:guide.org::#install]]= or =[[./guide.org]]=, leads to that page, as little leads a link to a page's file, and so does =[[file:../writing/markdown.md]]=, to a Markdown page.

* Lists

Each of Org's lists is the Markdown list nearest it:

- Bullets :: Items that start with =-= or =+=, or =*= indented, nested as they're indented, are a bulleted list.
- Numbers :: Items that start with =1.= or =1)= are a numbered list, which starts at 1, or where its first item's counter, like =[@4]=, says.
- Checkboxes :: =[X]= and =[ ]=, after an item's bullet, are GitHub's task lists, and =[-]=, for one partly done, is =[ ]=.
- Terms :: A term and what it means, like these, are a description list, in HTML, unless the =description_lists= extension is on.

* Code

A block of code, =#+BEGIN_SRC lang=, is a code block, highlighted in its language, and an example block, =#+BEGIN_EXAMPLE=, or a run of lines that start with =:= and a space, is one with no language.
Like a Markdown page's, a code block goes to [[file:using-plugins.md::#code-blocks][plugins]] that render its language, and a =mermaid= block is a [[file:../writing/diagrams.md][diagram]].
An inline block, like =src_python{print(1)}=, is code too.

Nothing is run, so a block shows what its =:exports= header says, =code=, the default, =results=, =both=, or =none=, with the results saved with it, under =#+RESULTS:=, as this one's are:

#+BEGIN_SRC python :exports both
print("Hello from Org mode")
#+END_SRC

#+RESULTS:
: Hello from Org mode

* Admonitions

#+BEGIN_NOTE
A special block named for one of GitHub's five [[file:../writing/markdown.md::#callouts][alerts]], =NOTE=, =TIP=, =IMPORTANT=, =WARNING=, or =CAUTION=, like this note, is that alert, and so is =HINT=, a tip, or =DANGER= or =ERROR=, a caution.
#+END_NOTE

An admonition can hold lists and code too.
Where your site turns the =alerts= extension off, an admonition is a quote that starts with its name, in bold.

* Other blocks

#+CAPTION: What other blocks are
| Block                                              | In the page                                                                                 |
|----------------------------------------------------+---------------------------------------------------------------------------------------------|
| Quote, =#+BEGIN_QUOTE=                             | A quote                                                                                     |
| Verse, =#+BEGIN_VERSE=                             | A paragraph for each stanza, with its line breaks and indentation                           |
| Center, =#+BEGIN_CENTER=, and other special blocks | What they hold                                                                              |
| Export, =#+BEGIN_EXPORT html=, and =#+HTML:=       | Its HTML, as it is, unless your site turns [[file:../writing/markdown.md::#html][HTML]] off |
| Export to another format, like =latex=             | Nothing                                                                                     |
| Horizontal rule, =-----=                           | A rule                                                                                      |
| Comment, =# text=, or =#+BEGIN_COMMENT=            | Nothing                                                                                     |

A caption, =#+CAPTION:=, is a paragraph in italics, above its table or block of code, as this table's is, or below its image.

* Tables

A table is one of GitHub's tables, with its header row, above its first rule, =|---+---|=, if it has one.
A table without a header row has an empty one, as Markdown's tables need one, which the built-in theme hides.
Each column is aligned as its cookie, =<l>=, =<c>=, or =<r>=, says, or else to the right if at least half its cells are numbers, as Org's export aligns it:

| Headline   | Heading     | Level |
|------------+-------------+-------|
| =* Title=  | =## Title=  |     2 |
| =** Title= | =### Title= |     3 |

The special column and rows of a table that Org's spreadsheet reads, and its row of cookies, are left out, as they are in Org's export.

* Images

A link to an image, like =[[file:diagram.png]]=, with no description, is the image, with the name of its file as its alt text, or the =:alt= of an =#+ATTR_HTML:= above it.
An image as a link's description, like =[[https://example.com][file:diagram.png]]=, is an image that's a link.

* Footnotes and their definitions

A footnote, =[fn:name]=, is numbered through the page, like this one.[fn:1]
Its definition, a line that starts with =[fn:name]=, can be anywhere in the file, like under a headline named =Footnotes=, at its end, which is left out, with all that's under it, as in Org's export, and an inline one, =[fn::Its text.]=, is defined where it is.

* Math

Math is TeX, written as [[file:../writing/math.md::#choosing-how-math-is-written][=markdown.math=]] says: =$…$= or =\(…\)= in a line, like $e^{i\pi} + 1 = 0$, and =$$…$$=, =\[…\]=, or a LaTeX environment, like =\begin{equation}=, on its own.
A dollar sign that Org wouldn't read as math, like those in $5 and $10, stays a dollar sign.

* What's different

The plugin reads Org as Org's own HTML export does, and leaves out what it leaves out, like comments, but:

- it runs no code, so a block shows only the results saved with it, and one whose =:exports= shows results it doesn't have is warned of, as is a =#+CALL:= line or an inline =call_name()=, which are left out;
- an include, =#+INCLUDE:=, isn't followed, as a plugin reads only the file it's given: it's warned of, and left out, and a setup file, =#+SETUPFILE:=, isn't read, so nothing it sets is set;
- any other macro, like Org's ={{{time(%Y)}}}=, or one that runs code, with =(eval=, is kept as text, and warned of;
- a headline's TODO keyword and tags, and its drawers, but a block's results, are left out, though Org's export shows them, as a page of docs has no use for them;
- no headline is numbered, whatever =num:= says, and each is a heading, to =######=, whatever =H:= says, where Org's export lists those past the third level;
- a link into Emacs, like =elisp:= or =info:=, or to a headline, target, or name the page doesn't have, keeps its text, and is warned of, and one to a search in another file, like =[[file:guide.org::*Install]]=, but a =#id=, leads only to its page, and is warned of;
- a table.el table is code, and a table's header rows after the first are joined to its body, as Markdown's tables have one, and both are warned of;
- a counter, =[@N]=, on an item after a list's first, that doesn't follow on from the item before, is left out, and warned of, as Markdown numbers a list only from its start.

The page is written as [[file:../writing/markdown.md][Markdown]] is, so [[file:../themes/styling-markdown.md][Styling Markdown]] shows the HTML it is, for a theme's CSS.
